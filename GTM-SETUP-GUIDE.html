Getting your clicks into GA4

The website already reports every button and link click. Nothing is listening on the other end. This guide builds the missing half — about 25 minutes of clicking in two browser tabs.

GTM container GTM-K6C53VGR GA4 property G-VCL4K7HGYJ ~25 minutes

Where the chain is broken

I verified the left half by running the site's real JavaScript against six pages (English, Greek, Chinese, plus the booking page) and simulating a Google Maps click — every one pushed ui_click with click_action: "directions". So no code changes are needed.

One event covers everything. The site emits a single ui_click event for every link and every button, with the action derived from the destination rather than the label — so Greek and Chinese buttons report identically. That is why you build one trigger instead of six, and why the older "Just Links" triggers in GTM-SETUP.md section 3 can be skipped entirely: they can never fire on a real <button> anyway, which is exactly the symptom you noticed.

Skip click_url and reservation_id as dimensions — both are high-cardinality and will burn your 50-dimension budget for little reporting value. They still arrive on the event and are visible in DebugView.

Turn the important ones into key events

Two of your events can be marked directly. Go to Admin → Data display → Events and toggle Mark as key event for reservation_complete and form_submit. They only appear in that list after they've been received at least once, so complete a real test booking first.

WhatsApp, Order Online, Directions and Phone clicks all arrive inside ui_click, so they need one extra hop. Admin → Data display → Events → Create event → Create, then build each of these four:

Three things that trip people up here. Created events only apply to data collected after you save them — nothing is backfilled. They won't appear in the Events list until GA4 has received one, so fire a test click first and give it up to 24 hours (DebugView is immediate). And click_action must be spelled exactly as the site sends it — directions and phone, singular, no _click suffix. The suffix belongs to the new event name, not the condition.
Verified against the code. These four values come from the rules table in assets/js/main.js, and I confirmed them by running the real script against the homepage: directions fires from the location block, final CTA and sticky bar; phone from the location block and footer. Both are identical in all six languages, because the action is derived from the link destination rather than the button label.

If you later want reserve (clicks through to the booking page) counted too, same pattern — but bear in mind reservation_complete already measures the outcome that actually matters, and counting both intent and outcome as key events will inflate your conversion total.

What you deliberately skipped

Sections 3 and 4.2 of GTM-SETUP.md describe six separate "Just Links" click triggers with six matching GA4 tags. They're superseded by ui_click, which is strictly better: it covers buttons as well as links, survives translation, and gives you placement data. Building both would double-count every click.

Google Ads conversion tags (section 4.3) also remain undone. They need a linked Ads account and a Conversion ID per action. Once you have that, the shortcut is to add a trigger condition on ui_click where click_action equals whatsapp, rather than building new tags — one dataLayer event feeding many destinations.
